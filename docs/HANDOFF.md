# סיכום הלילה: מה נבנה, מה הנחתי, ומה צריך להחליט

הגרסה הזו רצה **לוקאלית בלבד** (לא נעשה deploy). כדי לראות אותה: `npm start` ואז http://localhost:3000.
הכול נבדק: `npm test` (99 בדיקות יחידה ומאפיינים), `npm run check:bridge` (45 בדיקות Python לשירות Cookidoo) ו-`npm run e2e` (18 תרחישי דפדפן אמיתי, כולל בדיקת נגישות axe במצב בהיר וכהה בכל המסכים).

## מה בנוי

המסך הראשי נשאר עם שני הכפתורים הענקיים (**שרון** ו-**Thermomix**). לא החזרתי כפתור שלישי (הסרת אותו קודם), אלא שורת קיצורי דרך קטנה מתחתיהם.

| מסך | מה אפשר לעשות |
|---|---|
| **מתכונים** (`#/cook`) | 49 מתכונים מקוריים בפורמט Thermomix. חיפוש, קטגוריות, סינון לפי כשרות/תזונה/אלרגנים/זמן/קלוריות/עלות, מיון לפי חיסכון. בכל כרטיס: עלות למנה בבישול מול הזמנה. |
| **עמוד מנה** | כמות מנות משתנה (הכול מתעדכן), **בישול מול הזמנה** עם הפרש וחיסכון ב-%, כמה זה "משלם לשעת עבודה", עלות בכל חנות, קלוריות, אזהרה אם המרק לא ייכנס לקערה, הערות אישיות, תחליפים למצרכים, שיתוף/הדפסה. |
| **השוואת מחירים** (`#/compare`) | סל מנות: סה״כ בכל אחת מ-8 החנויות (אריזות שלמות, בניכוי המזווה, אפשרות למשלוח), הזול ביותר, **שתי חנויות** או **חנות לכל מצרך** (וכמה חוסכים), בישול מול הזמנה של הכול, מנות "כמעט בחינם" שמנצלות אריזות שכבר קונים, תקציב, שווי זמן. אפשר לשתף את הסל בקישור. |
| **רשימת קניות** | מסודרת לפי מדפים, סימון, פיצול לפי חנות, וואטסאפ/העתקה/הדפסה. |
| **מצב בישול** | מסך גדול שלב אחרי שלב, צ'יפים של זמן/טמפרטורה/מהירות, **טיימרים**, המסך נשאר דלוק, **הקראה בקול**, החלקה/חיצים. בסוף: "רשמתי שבישלתי" וסופר חיסכון. |
| **שרון** (`#/order`) | תפריט עם מחירים, סל הזמנה, הודעת וואטסאפ מוכנה (עם המספר של שרון), עריכת מחירון. אפשר להוסיף **מקורות הזמנה נוספים** (וולט, מסעדה...) והם נכנסים לכל ההשוואות. |
| **תכנון שבועי** | מה אוכלים כל יום; **תכנון אוטומטי** לפי תקציב והעדפות; רשימת קניות לכל השבוע; **ייצוא ליומן** (קובץ ICS). |
| **מזווה** | מה יש בבית (לא נספר בקנייה) ו"מה אפשר לבשל עכשיו?". |
| **מחירים** | טבלת מחירים לפי חנות, עריכה בלחיצה, ייבוא מטקסט. |
| **ייבוא מתכון** | הדביקו מתכון (למשל מ-Cookidoo, גם באנגלית) והוא מנותח למצרכים/כמויות/הגדרות מכשיר; עריכה ושמירה. **אופציונלי:** חיפוש וייבוא ישירות מחשבון ה-Cookidoo שלכם דרך שירות אישי (ראו למטה). |
| עוד | "מה לאכול הערב?", יומן בישולים והחזר השקעה במכשיר, הגדרות (כשרות, גודל טקסט, ערכת נושא, גיבוי/שחזור), אודות והצהרת נגישות. |

עוד: PWA (מתקינים כאפליקציה, עובד גם בלי אינטרנט), מצב כהה, ללא חשבונות וללא מעקב (הכול נשמר בדפדפן).

## החלטות והנחות שעשיתי בלי לשאול (כדאי לעבור עליהן)

1. **Cookidoo:** האתר חסום מהסביבה שבה עבדתי, והמתכונים שם בתשלום ומוגנים בזכויות יוצרים. לכן **כתבתי 49 מתכונים מקוריים** בסגנון Thermomix (הגדרות הזמן/טמפרטורה/מהירות הן הערכות סבירות שצריך לוודא על המכשיר שלכם), ובנוסף בניתי **ייבוא**: מעתיקים מתכון מ-Cookidoo (או מכל מקום) ומדביקים. בלי סקרייפינג. **עדכון:** נוסף גם חיבור אופציונלי לחשבון שלכם, ראו "חיבור ל-Cookidoo" למטה.
2. **אין נתוני דוגמה.** הרשתות המפורסמות באתרי המחירים (שופרסל, פורטל שקיפות מחירים) חסומות מהסביבה שלי, ולכן **אין באתר שום מחיר**: לא מחירי רשתות, לא מחירי הזמנה ולא דמי משלוח. מחיר מופיע רק אם הוזן ידנית (מסך מחירים, או הדבקת שורות `מצרך, חנות, מחיר`) או יובא מקובצי מחירים אמיתיים. סכום מוצג רק כשיש מחיר לכל המצרכים הנדרשים, ואחרת האתר אומר מה חסר. **צריך להחליט איך להביא מחירים אמיתיים** (ראו למטה).
3. **מי זה "שרון"?** לא ידעתי, אז הגדרתי "מקור הזמנה" כללי: תפריט שאפשר להזמין ממנו בוואטסאפ, בלי מחירים. אפשר להזין מחיר למנה בעריכת המחירון, ולהוסיף מקורות נוספים.
4. **"שווי הזמן":** ברירת המחדל 0. אם תזינו שווי לשעת עבודה (בעמוד ההשוואה או בהגדרות) הוא מתווסף לעלות הבישול.
5. **מזווה ברירת מחדל:** מלח, פלפל, סוכר, שמן ושמן זית נחשבים "בבית".
6. **כשרות:** מחושבת אוטומטית מהמצרכים, ובדיקה אוטומטית מוודאת שאין מתכון עם בשר וחלב יחד. (לא בדקתי השגחה/כשרות של מוצרים ספציפיים.)
7. **קלוריות:** משוערות מטבלאות כלליות (מסומן במסך).
8. הצהרת הנגישות נוסחה אוטומטית, ועדיין חסר בה **מייל/טלפון לפניות**. (`public/js/views/about.js`)

## חיבור ל-Cookidoo (אופציונלי, `bridge/`)

אין API רשמי של Cookidoo, אבל יש ספרייה לא רשמית ([cookidoo-api](https://github.com/miaucl/cookidoo-api)) שמתחברת עם אימייל וסיסמה. בניתי עליה **שירות Python קטן** (`bridge/`) שהאתר מדבר איתו: חיפוש מתכונים, ושליפת מתכון בפורמט שהייבוא הקיים כבר מכיר. מההגדרות באתר מזינים את כתובת השירות ואת הטוקן שלו, ואז **מקלידים אימייל וסיסמה של Cookidoo באפליקציה**. הסיסמה נשלחת פעם אחת, השירות בודק אותה מול Cookidoo (טעות הקלדה מתגלה מיד) ומחזיר "כרטיס כניסה" מוצפן שתקף כחודש. **הדפדפן שומר רק את הכרטיס הזה, לא את הסיסמה**, ושום דבר לא נשמר בשרת. הטוקן והכרטיס לא נכנסים לקובץ הגיבוי. אחרי 5 סיסמאות שגויות ב-15 דקות ההתחברות ננעלת, כדי שלא ינעלו לכם את חשבון Cookidoo. (אפשר גם חשבון קבוע בשרת, ראו `docs/COOKIDOO.md`.)

- המתכונים יגיעו **באנגלית** (לישראל אין עברית בספרייה). הפרסר הורחב לאנגלית: כמויות, יחידות, שמות מצרכים (נוספו שמות באנגלית לכל 99 המצרכים בקטלוג) והגדרות מכשיר כמו `5 min/100°C/speed 2`, Varoma, reverse, turbo.
- **ה-MCP של alexandrepa** עוטף את אותה ספרייה לעוזרי AI (stdio), ולכן אי אפשר לקרוא לו מדף אינטרנט. הוא יכול לרוץ במקביל לאותו חשבון, והכלים שלו להעלאת מתכונים אישיים עם הגדרות Thermomix הם בסיס טוב לתכונה עתידית "שלח מתכון ל-Cookidoo שלי".
- **לא נוסה מול Cookidoo אמיתי** (אין לי חשבון, והרשת שלי חסומה אליו). הכול נבדק מול נתוני דמה ומול מבני הנתונים של הספרייה. בהרצה הראשונה כדאי לעבור על הרשימה ב-`docs/COOKIDOO.md` ("First real run"); אם משהו נראה לא נכון, שולחים לי פלט גולמי של מתכון אחד ומתקנים עם בדיקה.
- **סיכון:** השימוש ב-API לא רשמי עלול להפר את תנאי השימוש של Cookidoo (לא בדקתי). זה חשבון שלכם ושימוש אישי, אבל זו החלטה שלכם. השירות מגביל את עצמו ל-60 בקשות בדקה ושומר מתכונים בזיכרון בלבד.
- איך מפעילים: `docs/COOKIDOO.md` (מקומית, או כשירות שני ב-Railway עם `BRIDGE_ORIGIN` באתר). בשיטת ההתחברות מהאפליקציה אין סיסמת Cookidoo בשרת בכלל.

## שאלות פתוחות

- **מה זה שרון?** (אדם / מסעדה / שירות?) והאם יש לו תפריט ומחירון אמיתי שאפשר להזין?
- **איך מביאים מחירים אמיתיים?** אפשרויות: (א) להריץ את `tools/ingest-prices.js` על קובצי המחירים של הרשתות (הכלי כתוב ומכוסה בבדיקות אבל לא נוסה על קבצים אמיתיים, ראו `docs/DATA.md`), (ב) להזין ידנית במסך המחירים, (ג) כלי אוטומטי שרץ מדי לילה (דורש שרת, אפשר לבנות).
- **איפה עושים deploy?** יש קונפיגורציה ל-Railway, Vercel ו-Netlify (`docs/DEPLOY.md`). כל אחד עובד.
- האם האתר ציבורי (אז כדאי לבדוק נגישות מול קורא מסך אמיתי) או רק לשימוש אישי/משפחתי?
- שם לאפליקציה ודומיין?

## צ'קליסט ל-deploy מחר

1. `npm run check` ו-`npm run e2e` ירוקים (מותקן אצלי; ב-GitHub Actions יש workflow שמריץ את זה, `.github/workflows/ci.yml`).
2. להחליט איך נכנסים מחירים אמיתיים (הזנה ידנית, או ייבוא קובצי מחירים).
3. להשלים פרטי קשר בהצהרת הנגישות.
4. לבחור פלטפורמה ולפי `docs/DEPLOY.md`.
5. לבדוק על הטלפון: התקנה כ-PWA, מצב בישול, טיימר, וואטסאפ.

## מגבלות ידועות

- נבדק רק ב-Chromium (בדיקות אוטומטיות). לא נבדק ב-Safari/Firefox ולא עם קורא מסך אמיתי.
- הקראה בקול תלויה בקול העברי שקיים במכשיר.
- אין שרת: הנתונים (סל, מחירים שהזנתם, מתכונים שיובאו) נשמרים במכשיר ובדפדפן אחד בלבד. יש גיבוי/שחזור לקובץ בהגדרות.
- הגדרות Thermomix במתכונים המובנים לא נבדקו על מכשיר אמיתי.
